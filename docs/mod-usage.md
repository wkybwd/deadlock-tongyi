# 通译（Tongyi）mod 使用说明（游戏内聊天翻译）

## 它做什么

| 场景 | 表现 |
|------|------|
| 别人发英文聊天 | 头顶气泡/聊天框里显示**中文译文**，原文以小字保留（`译文显示` 默认「双语」，可切成「替换原文」，悬停可看原文） |
| 别人发英文、翻译还没回来 | 那一条消息上先出现一个弱的 **`···`**（头顶气泡在原文下面另起一行；聊天框拼在正文那一格，像 `mid no \| ···`），译文到了**原地**换成中文。慢于 0.4 秒才显示，所以缓存命中的快消息不会闪 |
| 那一条翻不出来 | 同一位置变成 **`翻译失败`**（暖色），停留 6 秒后消失；具体原因看面板里的「最近错误」。期间会自动重试，最多 3 次 |
| 那条消息太长 | 译文会**主动截断**并加 `...`，状态行说明「译文过长，已截断显示」。不这么做的话整包会撞通道长度上限，表现为「翻译失败 / 未知原因」 |
| 你要说中文 | 打中文 → **连按两下空格**（默认触发键）→ 输入框自动变成中英对照 → 按回车发送（`我发出去的消息` 默认「中英都发」，可切成「只发英文」） |
| 别人用俄语说话 | 照样翻成中文（亚服/欧服混排常见）。以前这种消息会被当成「非英文」**静默丢掉** |
| 消息淡出后想再看 | 面板底部「**最近译文**」：列出本次对局翻过的最近若干条（原文 → 中文），再点一次翻更早的。游戏大约 10 秒就把聊天行淡出，之前没有任何办法回看 |

两件事都在游戏 UI 内部完成：不需要模拟按键、不做屏幕 OCR、不注入任何进程。
网络侧只有一个到本机 `localhost:8791` 的请求，译文由本地模型产出，不出网。

## 前置

1. **Ollama 在跑**（翻译模型本地推理，首次调用才载入显存）。
   *想用云端（默认）则不用装 Ollama，只要配一次 API Key，见 README）。*
2. **桥在跑**：双击 `start_bridge.bat`，保持窗口开着。
   自检：桥开着的时候跑 `python scripts\bridge_selftest.py`（协议 + 长度门禁 + 试翻）。
3. **mod 由 DMM 管理**：见下面「装进 Deadlock Mod Manager」。
   （本机约定：不用手动往 `addons` 里塞文件，那个目录归 DMM 管。）

装好之后游戏内输入框附近会有一行状态提示：

- `通译` —— 布局已加载但脚本/桥还没就绪（这行是布局里的固定初值，用来判断覆盖有没有生效）
- `通译 就绪（面板）` 或 `通译 就绪（直连）` —— 当前界面正常
- `通译 正在确认连接…` —— 当前界面的第一次探测失败，正在重试
- `通译 当前界面暂未连通` —— 当前聊天界面连续探测失败；头顶气泡使用独立通道，可能仍能翻译
- 完全没有这行字 —— 布局覆盖没生效（mod 没被加载）

## 游戏内界面：状态灯 + 设置面板

输入框那一行右侧是**状态灯**（7px 圆点）：

| 颜色 | 含义 |
|------|------|
| ⚪ 灰 | 当前界面尚未完成连接检测 |
| 🟢 绿 | 当前界面可用 |
| 🟡 黄 | 有一次连接波动，正在确认；成功翻译仍可继续 |
| 🔴 红 | 当前界面连续连接失败；先检查桥，再看面板中的诊断信息 |

> 不要期待"直连通道"的绿灯含义：引擎已经删掉了 `$.AsyncWebRequest`
> （`panorama.dll` 里写着 `ERROR: AsyncWebRequest has been removed.`），
> 所以隐藏 HTML 面板 + 事件读回是这个版本**唯一**的通道。
> 它是单槽串行、每条请求一次页面导航，比直连慢几百毫秒 —— 但能正常工作。

打开设置面板的两种方式（任选）：

1. **点按钮**：按回车打开聊天框 → 输入框那一行右侧的「设置」按钮
2. **聊天命令**：在聊天框里输入 `/tongyi`（或 `/通译`，旧命令 `/dlchat` 仍然可用）—— 检测到就清空输入并打开面板，
   这条命令不会被发出去

> F8 快捷键：代码里试过用 `$.RegisterKeyBind` 绑，但实测**按了没反应**，已经不再作为入口。
> 用上面两种方式，或者自己去 `mod/panorama/layout/*.xml` 里加。

面板按「收与发 / 聊天呈现 / 翻译引擎 / 连接与诊断」分组，改动后「保存更改」会突出显示。
可调整收发开关、译文显示方式（**默认双语**，可切替换原文）、悬停看原文、
**我发出去的消息（默认中英都发，可切只发英文）**、**中英之间的分隔符（默认 `|`）**、
触发键（**默认两下空格**，可切三下）、
**上下文轮数（默认 1 轮，可切 0/2）**、**翻译来源（本地 Ollama / DeepSeek 云端）**、
模型常驻时长、术语表、
**翻译模型**（列出**当前来源**可用的模型）、
顶部有「保存设置」（改动后显示「保存更改」）；底部有「试翻一句 / **重译最近一条** /
**最近译文** / 重新读取」，
以及桥状态与各方向中位延迟。

> **上下文轮数**只作用于"收到的消息"：`on him`、`no`、`push` 这类短句没有上一句
> 就没法确定指谁、否定什么，带上 1 轮（= 屏幕上刚过去的那一句）能明显改善。
> 0 = 每句独立翻（最省 token）；2 = 再往前记一句。**自己要说的话不带上文** ——
> 那是你要表达的内容，不需要屏幕上别人的聊天历史。
>
> 代价：每句请求的输入会多几十到两百个 token（前缀缓存仍然命中 system 段，
> 所以主要是输入费用，不是延迟）。

> **两种显示方式到底差在哪**（这里说的都是**聊天框**，头顶气泡不走这条路）：
> - 「**英文 | 中文**」（默认）：中文**拼在原文同一格**里，和你在输入框里看到的写法一致。
>   为什么不做成"气泡下面单独一行中文"：聊天区是游戏写死的 `height: 200px` +
>   `overflow: squish scroll`，最新一条又贴在容器边界上，输入框那一行（不透明黑底）
>   还是后画的兄弟节点 —— 挂在下面的那行中文会被裁掉/盖住，只有最新一条必然中招。
>   （最早用「替换原文」时没这毛病，就是因为中文画在气泡**内部**。）
>   代价：一条消息占的高度翻倍，聊天区能同时看到的行数变少。
> - 「**只显示中文**」：中文写进气泡、**盖掉**英文，英文原文悬停可看。消息最紧凑，
>   代价是默认看不到原文。

面板里还有一行**「最近错误」**：翻失败时它会留下原因（没配 Key / 被限流 / 桥没开 / 超时），
直到下一次翻译成功才消失。状态行那句提示几秒就没了、打团时根本看不到，这一行是给你事后回看的。

> 面板高 680px。如果你的分辨率特别小、
> 或者模型下拉展开后觉得挤，**面板中间那块可以滚动**。保存按钮固定在顶部，
> 试翻、重译和重读按钮固定在底部，不会被挤出去。

## 我用着觉得慢 / 翻错了，怎么办

| 现象 | 现在是怎么处理的 |
|---|---|
| 打完中文按空格，要等好几秒 | 你的翻译会**插队**（不排在屏幕上那堆聊天行后面）；旧消息改成**从最新的一条开始翻** |
| 同一句话翻了两遍 | 客户端记着翻过的句子，第二次**直接用**、不请求桥 |
| 某一句翻错了 / 第一次超时了 | 点面板底部「**重译最近一条**」 |
| 想知道刚才为什么没翻出来 | 看面板里的「**最近错误**」那一行（现在会把「回包被截断」「译文过长」这类也说清楚，不再是一句"未知原因"） |
| 翻译一直失败，输入框里的中文不动 | 同一句连续失败 2 次后会**停止自动重试**并明确告知（以前是每 0.1 秒打一个请求的死循环，还会把通道占满、屏幕上的聊天行全排在后面）。处理完重新按空格即可 |
| 打的中文带了换行，发出去变成两条 | 翻译前会把换行和连续空格**压成一个空格** |
| 中英之间那个 `\|` 在游戏里显示得很怪 | 点「中英之间的分隔符」换另一种（`\|` / `｜` / 两个空格） |

> 分隔符三种都给出来，是因为"竖线在游戏字体里到底渲染成什么样"只能进游戏才看得出来：
> 不对就点一下换下一个，不用重装 mod。


## 切换翻译来源（本地 / DeepSeek 云端）

1. 在聊天框输入 `/tongyi`（或点输入框那行的「设置」）打开面板 → 点**「翻译来源」**那一行，
   在 `本地 Ollama` 和 `DeepSeek 云端` 之间来回切。
2. 切完自动去读**该来源**的模型列表，并默认选第一个（云端就是 `deepseek-flash`）；
   要换就点「翻译模型」。
3. 点「保存并生效」。桥会当场换端点、把模型名换成该来源有效的那个，并清空翻译缓存。

云端来源要注意三件事：

* **第一次要先配 API Key**：浏览器打开 <http://localhost:8791/settings> 填一次，
  永久生效（那一页只有这一个输入框）。没配的话面板状态行会直接写
  「⚠ 没配 API Key」，不用猜。
* **聊天内容会出网**：本地来源是"聊天不出本机"，切到云端就不再成立了 ——
  面板状态行的前缀会显示成 `DeepSeek` 提醒你。
* **「模型常驻」那一行会自动收起来**：那是 Ollama 的 keep_alive，对云端没意义。
* 云端失败不会自动回退本地：状态灯变黄/红，状态行给具体原因
  （Key 无效 / 欠费 / 限流 / 超时），切换来源即可回本地。


## 怎么确认用的是"我们自己的"翻译

游戏里没法看 console，所以 mod 会把每一步推到桥上：

```bat
python scripts\mod_log.py            :: 读最近的游戏侧日志
```

会看到 `[tongyi-mod/1.0.0] boot {...}`、`in:mid no => 中路没人`、`out:小心绕后 => watch out for flank`
这样的记录。**只有我们的 mod 会写这些行**；如果游戏里翻译生效但这里一条都没有，
说明生效的是别的翻译工具（例如 BabelTower）。

## 装进 Deadlock Mod Manager（DMM）

**本机只走这条路**：`addons` 目录归 DMM 管，我们不再手动往里塞文件。

原因（实测）：DMM 会**接管** `Deadlock\game\citadel\addons\`，把每个启用的 mod 部署成
一份 `pakNN_dir.vpk`（序号就是加载顺序），并且在你卸载 mod 时会顺手删掉它认为属于那个
mod 的 VPK。我们手动放进去的 `pak01_dir.vpk` 就这样被删过一次
（DMM 日志 `Purging mod ... Removed VPK: pak01_dir.vpk`）。所以要么全程 DMM 管，
要么全程手动管，别两头都管。

### 导入步骤

导入源（每次重新编译后这个文件就是最新的；**是一个文件，不是一个文件夹**）：

```
C:\Users\Hlliang\Desktop\deadlock-tongyi\build\tongyi-pak01_dir.vpk
```

1. DMM → **My Mods**
2. 点**添加本地 mod / 导入本地文件**那个按钮（当初装 BabelTower 用的就是这个流程）
3. 选中上面那个 **`.vpk` 文件**（DMM 也接受 `pak01_dir.vpk` / `pakNN_dir.vpk` 这种文件名）
4. 起个名字，例如 `通译`
5. **启用** → 点 **Launch Modded** 启动游戏

> 以前这里让用户"选文件夹 `dist_mod\dlchat_local`"，所以打包器得把同一个包写两份
> （根目录一份、导入目录一份）。两份一旦分叉，表现就是"我改了但游戏里没变化、
> 而且不报错"。2026-09-20 起只产出一份，直接选这个文件即可。

DMM 会把文件复制进自己的库
（`%LOCALAPPDATA%\dev.stormix.deadlock-mod-manager\mods\local-<uuid>\files\`），
再按加载顺序部署到 addons，之后启用/禁用/排序都在 DMM 里操作。

### 更新 mod

DMM 目前不支持"更新"（作者建议删掉再加一次）：

```bat
python scripts\stage_compile.py --pack     :: 只编译打包，不碰 addons
```

然后把 `build\tongyi-pak01_dir.vpk` 重新导入一次，或在 DMM 里卸载旧的再加新的。

### 注意

- **别和 BabelTower 共存**：两个 mod 都覆盖 `chat.vxml_c`，谁生效取决于 `pakNN` 序号，
  表现会很难判断。用我们这个就把 BabelTower 卸干净。
- `addons\pak01_dir.vpk.bak`（180853 B）是 BabelTower 那份包的手动备份，确认不需要就删掉。
- 编译脚本默认**只打包不安装**（`--install` 是显式选项）。本机走 DMM，所以日常只用 `--pack`。

## 排查

**2026-10 HTML 通道变化：** 当前游戏会把 HTTP `SetURL` 地址替换成空白页，旧版因此一直显示「面板未加载」，桥日志也没有游戏请求。当前源码改用图片尺寸回传，回包有长度、CRC 和请求 ID 校验；必须同时更新桥启动器和 DMM 中的 VPK。该通道只访问本机，不需要安装证书。图片请求失败、回包校验失败和超时会在「连接与诊断」显示具体原因。

**2026-09-30 大版本更新：** 如果弹出 `Unable to find child 'TargetHeroImage'` 或
`Unable to load snippet TypingIndicatorChatMessage`，是旧 mod 覆盖了新版官方聊天布局。
请安装适配 Build 25614556 的新包；只重启桥或重填 Key 无法解决。DMM 清单为空也不代表
`addons` 没有旧 VPK：先退出游戏，备份并移出未被 DMM 管理的旧通译包，再只导入一份新包。
需要临时恢复原版时使用 DMM 的 Launch Without Mods，不要把旧版 `gameinfo.gi.bak` 整份覆盖回来。

| 现象 | 原因 / 处理 |
|------|-------------|
| 状态行一直"桥未运行" | 桥没起、或被 DMM/杀软拦了；桥开着时跑 `python scripts\bridge_selftest.py` 验证 |
| 译文是问号/乱码 | 标题通道编码问题（已在桥页面做 `\uXXXX` 转义）；把 `python scripts\mod_log.py` 的输出发我 |
| 气泡没变化 | 该条被判成"自己发的"（发出去的英文我们不再翻回中文）或不是英文 |
| 气泡下面挂着 `···` 一两秒 | 正常：这就是"正在翻译"的提示（英→中中位 1.2 秒）。同一句在屏幕上出现两次时，两条会一起变——它们共用一次请求 |
| 出现 `翻译失败` | 那一条没翻出来（桥不通 / 超时 / 没配 Key），行上提示停 6 秒；原因看面板「最近错误」，修好后点「重译最近一条」 |
| 装不上（WinError 32） | Deadlock 没退干净；`scripts\stage_compile.py --install` 会先检查游戏进程 |
| 装了没效果 | DMM 可能把 `pak01_dir.vpk` 合并回它自己的版本——在 DMM 里停用 BabelTower，或装完别再点应用 |
| 聊天框里**最新一条**的中文看不见（旧消息正常） | 老版本的老毛病：译文被挂在气泡**下面**，正好落进"聊天区边界 + 输入框黑底"那块。现在默认双语走**行内拼接**（中文写进正文那一格），不会再发生。若你把显示方式切回「替换原文」也不会——那条路中文在气泡内部。 |
| 想回退 | `addons\pak01_dir.vpk.bak` 就是装之前那个文件，改名覆盖回去即可 |

## 三个设计取舍（为什么这么做）

1. **不拦回车、不等翻译**。译文是"就地替换输入框文本"，玩家看完自己按回车。
   之前的实现是拦下发送、等翻译返回才放行——聊天框会卡着不关，手感很差。
2. **聊天框的译文和原文并排、但在同一格**。对局里视野宝贵，一行中文比"另起一行"更省地方，
   而且"另起一行"那版会被聊天区的裁切边界吃掉（见上面「两种显示方式到底差在哪」）。
   头顶气泡不适用：它没有那个固定高度容器，译文照旧单独排一行。
3. **不翻译自己发的消息**。你打的中文已经转成英文发出去了，再把这条英文翻回中文纯属浪费
   （用发出的文本 + 45 秒时间窗识别）。
